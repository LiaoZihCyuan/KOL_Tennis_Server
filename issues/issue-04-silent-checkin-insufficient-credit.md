# Issue 04：簽到時點數不夠會「靜默跳過扣點」，小編完全不會發現

**嚴重程度：中高**　**分類：點數邏輯**　**狀態：已修正 (2026-08-17，隨 Issue 05 一併處理)**

## 修正內容（實際採用的方向跟原本建議不同）

小編回饋：「簽到不應該會有點數不夠的問題，因為模板生課是要有點數才會產生相應的課程，且如果臨時加課也應有點數學生才能加課」。因此改成**從根源（約課當下）就擋掉點數不足的情況**（見 Issue 05），而不是在簽到那一刻才用警示訊息補救：

- `services/course_service.py` 的 `_deduct_student()`（原本的簽到扣點邏輯）拿掉了「`if b.student.credits >= course.credit_cost`」這個會靜默跳過扣點的判斷式，改成一律確實扣點（並同步扣 1 堂數，見 Issue 09-b／堂數設計）。因為 Issue 05 已經在約課／固定課表自動生課時擋掉點數不足的學員，正常情況下簽到已經不會再遇到點數不夠的狀況；萬一真的因為特殊狀況（例如約課後小編手動調低了點數）出現餘額不足，系統會照實扣成負數，並在後端 log 留下警告紀錄，而不是像修正前一樣完全沒有任何痕跡地跳過。

## 實測驗證

見 `issue-05-no-credit-check-on-booking.md` 的實測記錄（約課擋單、模板略過學員、簽到/請假同步扣退點數與堂數）。

## 問題敘述

課後簽到扣點的邏輯：

```python
# routes/course_routes.py:242 checkin_course
for b in bookings:
    b.status = BookingStatus.ATTENDED
    if b.student and b.student.credits >= course.credit_cost:
        b.student.credits -= course.credit_cost
        tx = CreditTransaction(...)
        tx.save()
    # 如果 credits < credit_cost，就什麼都不做：不扣點、不建交易紀錄、不回傳任何錯誤或警告
```

當學員點數餘額不足以支付這堂課時，`Booking.status` 依然會被標記成 `ATTENDED`（出席），但**扣點會被靜默跳過**：不會產生 `CreditTransaction`，前端也只會收到「簽到點名成功！」的成功訊息 (`routes/course_routes.py:284`)，完全沒有任何提示告知小編「這位學員點數不夠，其實沒扣到」。

## 重現步驟

1. 把學員點數改成 0（或小於這堂課的 `credit_cost`）。
2. 幫這位學員排一堂課，等於是「他點數不夠但還是被排進課表」（見 #05，排課本身也不檢查餘額）。
3. 對這堂課按「簽到出席」。
4. 前端跳出「簽到點名成功！課程已標記為已完成。」— 看起來一切正常。
5. 檢查該學員點數 → 沒有變化（因為原本就是 0，不夠扣）；檢查交易紀錄 → 沒有這筆扣點紀錄。

## 影響

- 學員可以在點數用完的情況下持續「被簽到出席」上課，但系統完全沒有留下任何「點數不足」的痕跡，小編如果只看課表（顯示已完成）不會發現異常，等於變相讓學員免費上課。
- 之後小編想稽核「這個月哪些學員是超額上課、需要提醒補儲值」時，沒有資料可查（因為沒有任何交易紀錄或狀態能反映「扣點失敗」這件事）。

## 建議修復方向

- 至少在點數不足時，簽到 API 回傳一個警告訊息（例如 `"warning": "王小明點數不足，本次上課未扣點，請提醒學員儘速儲值"`），讓前端跳出明顯提示給小編看。
- 或者允許點數扣成負數（並在學員個人頁 / 統計頁明顯標示「點數不足」），但無論哪種做法，都不應該讓扣點失敗這件事完全無聲無息地發生。
