# Issue 01：新增使用者表單缺少電話欄位，無法比照慣例直接發帳號

**嚴重程度：高**　**分類：使用者管理**　**狀態：已修正 (2026-08-17)**

## 修正內容

- `templates/add_user.html`：新增「電話」輸入欄位，並在表單送出時一併帶上 `phone`。
- `services/user_service.py`：`UserService.create_user` 若小編未填「預設密碼」但有填電話，會自動以電話號碼作為預設密碼（比照 `seed_data.py` 既有慣例），小編只要填電話就能直接把帳密（電話／電話）交給學員。
- 順帶補上原本註解宣稱存在、但實際沒有實作的「電話號碼重複」檢查，避免兩位使用者共用同一支電話，影響電話登入與 LINE 綁定比對的正確性。
- 本次僅補「電話」欄位（本問題描述中小編明確點名的欄位）；暱稱／性別／教練顏色欄位仍缺，維持原問題敘述，尚未修正，如需要可另外排入。

## 問題敘述

小編透過「新增使用者」頁面 (`templates/add_user.html`) 建立學員 / 教練帳號時，表單上**沒有「電話」欄位**，也沒有暱稱、性別、教練顏色欄位。但：

- 後端 `User` model (`models/user.py:35`) 有 `phone` 欄位。
- 後端 `UserService.create_user` (`services/user_service.py:47`) 完全支援接收 `phone`。
- 使用者列表的「編輯」彈窗 (`templates/user_list.html:239,263`) 有 `editPhone` 欄位，可見電話欄位在系統設計上是存在且重要的，只有「新增」表單漏掉。

對照 `seed_data.py`（CSV 匯入既有 26 位學員的腳本）：

```python
# seed_data.py:185
password_hash=generate_password_hash(phone),  # Password = phone number
```

可以看出這個系統既有的慣例是「**密碼＝手機號碼**」，登入時 identifier 也支援用手機號碼登入 (`routes/auth_routes.py:37`)，LINE 一鍵登入的綁定機制 `line_bind_student` 也是**用手機號碼去比對學員資料** (`routes/auth_routes.py:147-154`)。

但小編用網頁「新增使用者」建立的新學員，因為表單沒有電話欄位：

1. 無法比照舊生慣例，用「手機號碼」當帳密發給學員。
2. 新學員之後想用 LINE 一鍵登入綁定時，系統會用手機比對學員資料 (`line_bind_student`)，但這個學員完全沒有 `phone` 欄位資料，**永遠比對不到，無法完成 LINE 綁定**，只能回頭手動用帳密登入。
3. 建立完後小編必須立刻進「使用者列表」再編輯一次補電話（以及暱稱／性別／教練顏色），多一道工。

## 重現步驟

1. 登入小編帳號，前往「新增使用者」。
2. 檢視表單欄位：顯示名稱、Email、LINE ID、角色、初始點數、密碼、等級、偏好場地、備註 — 沒有電話欄位。
3. 建立一位學員後，到「使用者列表」點擊編輯，會看到「電話」欄位是空的，需要另外手動補上。

## 影響

- 小編無法用一致、既有的方式（手機當帳密）發帳號給新學員。
- 新學員無法透過 LINE 綁定登入（系統主打的免密碼登入流程），因為比對條件（電話）是空的。
- 多一道「新增後馬上要編輯補資料」的重複工。

## 建議修復方向

在 `templates/add_user.html` 的表單補上：
- `phone`（電話，建議設為必填，或至少在角色＝學員時必填，因為這是登入 / LINE 綁定的關鵼欄位）
- `nickname`（小名）
- `gender`（性別）
- `color`（教練顏色，角色＝教練時顯示）

並可考慮：若小編未填密碼、且角色為學員、且有填電話，前端或後端自動以電話號碼作為預設密碼（比照 `seed_data.py` 的既有慣例），維持新舊學員帳密邏輯一致。
