# Issue 05：約課 / 套用課表模板完全不檢查點數餘額

**嚴重程度：中**　**分類：點數邏輯**　**狀態：已修正 (2026-08-17)**

## 修正內容

- `services/course_service.py` `create_course()`：非體驗課、有指定學生時，建立課程前會先檢查該學生 `credits >= credit_cost`，不足就丟出 `ValueError`（對應 API 回 400，訊息例如「王小明點數不足（剩餘 1 點，本堂課需要 2 點），請先為學員儲值後再排課」），課程與預約都不會建立。手動幫學員臨時加課，現在真的需要學生有足夠點數才能加進去。
- `services/course_service.py` `generate_courses_from_templates()`：固定課表模板自動生課時，逐一檢查 `student_ids` 內每位學生的點數是否足夠。點數不足或學生不存在的**只跳過該學生的預約**，並記錄到回傳結果的 `skipped` 清單（course 本身、教練時段仍會照常產生，避免因為一位學生點數不夠就讓整堂課消失）。
- `routes/course_routes.py` `apply_templates_to_week`：把 `skipped` 清單併入回傳訊息，小編套用課表後若有學員因點數不足被跳過，會直接在成功訊息裡看到「有 N 位學員因故未被排入：王小明（點數不足...）」，不會悄悄發生。
- `static/assets/js/calendar.js` 新增課程的送出邏輯，原本 `res.ok` 為 false 時只會丟出固定文字「新增課程失敗」，看不到後端真正的錯誤原因；已改成優先顯示後端回傳的 `error` 訊息，小編才看得到「點數不足」這類具體原因。

## 實測驗證（dev 環境真實 API）

1. 學員剩 1 點，臨時加一堂需要 2 點的課 → 直接被擋下（400 + 具體錯誤訊息），沒有建立課程或預約。
2. 同一位學員加一堂剛好 1 點的課 → 成功建立。
3. 建立一位 0 點的學員，幫他建一個固定課表模板，套用到某一週 → 教練的課still正常產生，但該學員沒有被排入預約；API 回應訊息清楚列出「測試學員D（點數不足（剩餘 0 點，需要 1 點））」。

測試完成後已清除所有測試資料。

## 問題敘述

無論是行事曆手動新增單堂課 (`CourseService.create_course`, `services/course_service.py:22-63`)，還是套用每週固定課表模板批次產生課程 (`CourseService.generate_courses_from_templates`, `services/course_service.py:176-234`)，在建立 `Booking` 時**都沒有檢查學員當下的點數餘額**，只要學員存在，不管點數是 0 甚至已經是負的，一樣可以被排進課表、產生 `CONFIRMED` 的預約。

結合 #04（簽到時點數不足會靜默跳過扣點），實際的使用者路徑會是：

1. 學員點數用完了，但小編（或每週固定課表模板自動產生的課）沒有攔阻，照樣把他排進下週課表。
2. 學員照常來上課，小編照常簽到。
3. 因為點數不夠，扣點被靜默跳過（#04），沒有任何紀錄或提示。

也就是說，目前系統對「點數不足」這件事，從約課到簽到全程都沒有任何攔截或提示點，完全依賴小編自己手動去記憶/查詢每位學員的剩餘點數，才知道該不該繼續幫他排課。

## 重現步驟

1. 把學員點數改成 0。
2. 到行事曆手動幫他新增一堂課，或是套用該學員所屬的固定課表模板到某一週。
3. 系統正常建立課程與預約，完全沒有跳出任何「該學員點數不足」的警告。

## 影響

- 小編若沒有主動先去「使用者列表」或「學員統計」頁查點數，很容易誤幫點數已用完的學員繼續排課。
- 固定課表模板是「自動每週產生課程」(`CourseService.get_courses` 內會自動呼叫 `generate_courses_from_templates`)，代表就算沒有小編手動操作，系統本身也會自動、持續地幫點數已經用完的學員繼續產生新課程與預約，問題會隨著時間自動擴大。

## 建議修復方向

- 在新增課程 / 套用課表模板產生預約時，若該學員當下點數 < 這堂課的 `credit_cost`，至少要有明確提示（例如新增課程的確認視窗顯示「⚠️ 王小明目前僅剩 0 點，此堂課需要 1 點，請提醒儲值」），讓小編可以自行決定要不要繼續。
- 對於固定課表模板自動產生的部分，可考慮增加一個每週/每月的「點數不足學員」清單或提醒，讓小編能主動追蹤。
