## 核心結論

1. **後端其實已經有「點數＝時數」的換算邏輯**（`CourseService.hours_to_credit_cost`：1 小時 = 1 點，四捨五入），原本只在「新增課程」這一條路徑上有真正套用；請假退點、簽到扣點、調課、介面文案等其他路徑都沒有跟著這個換算邏輯走，導致點數在各種操作組合下兜不起來。這條邏輯現在已經在新增課程、請假/取消、簽到、狀態下拉選單、刪除課程、調課（含拖曳調整時長）**全部路徑上一致套用**（#02、#03、#06、#08 皆已修正）。
2. **新增使用者表單本身缺欄位**，跟資料庫 schema、編輯彈窗、既有慣例（密碼＝手機號碼、LINE 綁定比對手機號碼）都對不上，導致小編用網頁新增的學員無法直接比照舊有 26 位學員的方式拿到帳密（#01 已修正）。
3. **2026-08-17 追加設計決策**：小編確認「點數」與「堂數」都要記錄，且點數才是唯一真正的餘額（`models/user.py` 新增 `lesson_count` 欄位）；同時把「點數不足」的檢查點從「簽到才發現」前移到「約課/固定課表自動生課當下」（#04、#05），讓簽到在正常情況下不會再遇到點數不夠的狀況。
4. **資料一致性收尾**：課程被刪除時，現在會一併軟刪除底下的預約並清算已扣點數，統計/個人檔案查詢也補上了對應的過濾條件，避免已刪除課程還「陰魂不散」地出現在報表裡（#09）。

## 目前狀態

Issue 01～06、08、09 都已修正並在 dev 環境用真實 API 呼叫驗證過。#07（續課堂數包與實際點數換算的落差）已改為「點數是唯一真正餘額、堂數僅供參考」的設計並記錄取捨，屬於刻意接受的行為，非 bug。

#10（側邊選單手機不響應）、#11（教練統計互相看得到）已修正並實測驗證。#12（教練體驗過於唯讀、缺自助功能）牽涉「要不要開放教練自助標記出席/請假、要不要露出學生電話」等商業決策，建議先跟場館確認方向再排入修復。
